# Github Star Describe

一款 macOS 本地应用（SwiftUI + SwiftData），用于把你 GitHub 账号下所有 Star 过的仓库同步到本地，并为每个仓库维护一份**你自己的中文功能描述**——支持手动编辑，也支持通过兼容 OpenAI 协议的 AI 网关批量自动生成。适合用来管理个人收藏、沉淀知识库。

## 功能特性

- **同步 GitHub Stars**：输入 GitHub 用户名，自动分页拉取全部 Star 仓库（含 Star 数、语言、原作者描述、标星时间），本地自动新增/清理/更新。
- **自定义描述**：每个仓库可编辑独立描述，原作者描述始终保留供参考；手动编辑过的描述不会被批量 AI 覆盖。
- **AI 生成描述**：
  - 兼容 OpenAI 协议网关（可自定义网关地址与模型名称，API 密钥安全存储在 Keychain）。
  - 「检测验证」一键校验密钥与网关连通性。
  - 单个仓库生成后弹出对比确认窗口，确认后才替换。
  - 工具栏一键「批量描述」：按当前卡片顺序逐个生成，可取消，结束汇报成功/失败数量。
- **搜索与排序**：按仓库名、描述、语言搜索；支持名称、Star 数、标星时间六种排序。
- **卡片 / 列表双视图**：自适应网格卡片或紧凑列表，一键切换。
- **主题与背景**：5 套主题色（默认 / 深海 / 极光 / 暖阳 / 熏衣草），支持自定义背景图片与透明度。
- **数据备份**：将自定义描述导出为轻量 JSON 备份文件，也可从备份文件导入恢复。

## 环境要求

- macOS 26.2 及以上（工程 deployment target 为 26.2）
- Xcode 16.x 及以上

## 构建与运行

用 Xcode 打开 `Github Star Describe.xcodeproj`，选择 `Github Star Describe` scheme 直接 Run 即可（App Sandbox 已开启，数据全部保存在本机）。

命令行构建：

```bash
xcodebuild -project "Github Star Describe.xcodeproj" -scheme "Github Star Describe" -configuration Release build
```

## 使用方法

### 1. 同步你的 GitHub Stars

1. 在工具栏输入框中填入你的 **GitHub 用户名**（点击回车或右侧刷新图标均可触发同步）。
2. 同步完成后会弹出提示，显示获取总数、新增数和清理数。
3. 数据默认按「标星时间（新到旧）」排列，最新收藏排在最前。

同步基于 GitHub 公开 REST API（匿名访问，有 60 次/小时速率限制）；`GitHubService` 中预留了 Personal Access Token 字段，如需要可在此基础上提升限额。

### 2. 编辑自定义描述

点击卡片右下角的「编辑」图标（或列表行对应按钮）打开编辑弹窗：

- 在「我的功能描述」中输入你自己的描述，下方会展示原作者描述供参考；
- 内容实际发生变化时，该仓库的描述来源自动标记为「手动」，之后批量 AI 描述不会再覆盖它；
- 弹窗右上角可一键在浏览器中打开该仓库的 GitHub 页面。

### 3. 配置并使用 AI 描述

1. 点击工具栏「调色板」图标打开设置，在「AI 描述」一栏填写：
   - **网关地址**：兼容 OpenAI 协议的网关域名（默认 `ai.nandielinghai.de`，自动补全 `https://` 与 `/v1` 路径）；
   - **模型名称**（默认 `gpt-5.6-luna`）；
   - **API 密钥**：输入后自动存入系统 Keychain，下次打开应用自动回填。
2. 点击「检测验证」，确认返回「验证成功」后再开始使用。
3. 两种生成方式：
   - **单个生成**：点击卡片上的「魔棒」图标，生成后弹出对比窗口（当前描述 vs AI 新描述），确认「替换描述」后生效，并带 AI 来源小标记；
   - **批量生成**：点击工具栏右上角「魔棒」按钮，按当前卡片排列顺序（含搜索过滤与排序）逐个生成。只处理描述来源为「初始」（原作者描述）的仓库，手动编辑过或已 AI 生成过的自动跳过；中途可取消，结束后汇报成功/失败统计。

### 4. 搜索、排序与视图切换

- 顶部搜索框支持按仓库名、描述、语言过滤；
- 工具栏「排序」菜单提供六种排序：名称 A-Z / Z-A、Star 数高到低 / 低到高、标星时间新到旧 / 旧到新；
- 工具栏「网格 / 列表」图标在卡片视图与列表视图之间切换。

### 5. 主题与背景

在「调色板」设置中：

- 切换 5 套主题色彩，卡片背景、强调色、边框色随之变化；
- 「选择背景图片」可设置自定义背景，并用滑块调节透明度；「清除背景图片」恢复系统默认背景。

### 6. 导出 / 导入数据备份

- **导出**：设置 →「数据管理」→「导出自定义描述…」，生成只含仓库 ID 与自定义描述的 JSON 文件（默认文件名 `StarNotes_Backup`），便于迁移或换机恢复；
- **导入**：「导入备份文件…」选择 JSON 后，按仓库 ID 匹配并更新对应描述（导入的描述视为手动来源，不会被批量 AI 覆盖）。

备份文件格式：

```json
[
  { "id": 123456789, "customDescription": "这里是自定义描述" }
]
```

## 描述来源与覆盖规则

每个仓库的描述有一个来源标记，决定谁能覆盖它：

| 来源 | 含义 | 会被批量 AI 覆盖？ |
| --- | --- | --- |
| 初始 | 同步时带入的原作者描述 | 是 |
| AI | AI 生成并确认的描述 | 是（批量跳过，但可点卡片上的 AI 按钮重新生成） |
| 手动 | 用户实际修改过的描述 | 否（优先级最高） |

## 数据存储位置

- 仓库数据与描述：SwiftData 本地数据库（应用容器内）；
- API 密钥：系统 Keychain（`nan.Github-Star-Describe`），不随应用包分发；
- 自定义背景图：应用容器 `Documents/custom_background.jpg`。

## 常见问题

- **同步失败「无法拉取数据」**：检查网络与用户名拼写；匿名 API 有速率限制（60 次/小时），频繁重试会触发 403，稍后再试。
- **AI 检测验证失败**：确认网关地址、模型名称拼写正确，以及密钥有对应模型的访问权限；常见错误会直接展示网关返回的 HTTP 状态与摘要。
- **批量描述提示「没有可描述的仓库」**：说明所有仓库的描述都已手动编辑或已生成过 AI 描述，如需更新请对单个卡片点击 AI 按钮重新生成。
- **换电脑迁移**：用「导出自定义描述」备份 JSON，在新机器上同步同一用户名后「导入备份文件」即可。
